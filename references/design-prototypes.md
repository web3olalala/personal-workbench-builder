# Three clickable UI directions

Use after functional confirmation and before final implementation.

## Deliverable

Build three runnable routes or entries—commonly `/design/a`, `/design/b`, and `/design/c`—inside an isolated prototype area. Each must support enough interaction to test navigation, hierarchy, one core workflow, empty states, and responsive behavior. Example data must be clearly marked.

Do not submit images or prose descriptions as the three options.

## Meaningful difference

The directions must differ in at least four structural dimensions, not just color:

- navigation model;
- page composition and module grouping;
- information hierarchy and density;
- typography and spacing rhythm;
- card/list/table treatment;
- interaction pattern and progressive disclosure;
- mobile adaptation.

Derive all three from the confirmed workflow and aesthetic signals. A reference screenshot contributes visual language—palette, scale, density, rhythm, shape, and motion—not copied logos, text, assets, or exact layout.

## Review

Run the prototypes and give the user a direct way to open them. Ask the user to click through and choose A, B, C, or a clearly described combination. Record what is liked and disliked, not only the letter. Set `ui_confirmed` only after explicit selection.

Prototype code can be discarded or refactored after selection, but do not let it overwrite existing production code or data.
