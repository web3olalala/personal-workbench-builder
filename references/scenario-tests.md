# Invocation scenario contract

These scenarios define expected routing. `scripts/validate_scenarios.py` verifies that every contract has supporting language in the Skill or references; it is not a substitute for a live end-to-end product test.

1. “Initialize my personal workbench.” → inspect the directory, initialize state, and begin discovery; do not scaffold product code.
2. “I create Xiaohongshu content.” → explore the user's actual inspiration-to-review flow and current tools; do not apply a generic creator template.
3. “I don't know what features I need.” → infer candidates from role, workflow, pain, repeated tasks, and long-term records.
4. “I have no reference image.” → explore mood, density, color, apps, brands, or culture; if still unknown, propose three distinct directions.
5. A reference screenshot is supplied. → extract visual language without copying protected assets or exact layout, then create three clickable directions after feature confirmation.
6. “Phone and computer must sync.” → use cloud-sync mode with authentication, ownership, server-enforced isolation, and cross-device tests.
7. “I will use it every day.” → evaluate production hosting and PWA; do not leave the result only in a temporary preview.
8. “Find AI news for me every day.” → evaluate source, network/API/RSS, scheduler, authorization, and cost before implementation; do not fake a feed.
9. “Add a daily review.” → read existing project and state, assess impact, migrate safely, implement incrementally, and rerun QA.
10. “Redesign the home page.” → preserve functions and existing data, unless the user explicitly changes scope.
